## 0. 现状速查

| 部件 | 位置 / 说明 |
| --- | --- |
| 前端静态文件 | `/opt/fcdzy/www`（以只读方式挂载进 nginx 容器） |
| 后端 jar | `/opt/fcdzy/backend/fcdzy-site-1.0.0.jar` + 同目录 `Dockerfile` |
| Nginx 配置 | `/opt/fcdzy/nginx/conf.d/fcdzy.conf` |
| HTTPS 证书 | Let's Encrypt，`/opt/fcdzy/certbot/conf/live/fcdzy.xyz/` |
| 环境变量（密钥） | `/opt/fcdzy/.env`（权限 600） |
| 编排文件 | `/opt/fcdzy/docker-compose.yml` |
| 数据库 | 你已有的 MySQL 容器（跑在 `fcdzy-net` 网络里，不对外暴露端口） |
| 上传兜底目录 | `/opt/fcdzy/uploads`（图片主要走 OSS） |
| 数据库备份 | `/opt/fcdzy/backups`（cron 每天 3:00） |

容器名：`fcdzy-backend`、`fcdzy-nginx`；MySQL 容器名以 `docker ps` 为准。

**关键约定**：后端所有敏感配置只走 `.env` 环境变量，jar 里不含任何密钥；数据库地址在容器内用 MySQL 容器名解析，不连公网 IP。

## 1. 先看这张表（决定要做什么）

| 你改了什么 | 需要执行 | 要重启吗 |
| --- | --- | --- |
| Vue 页面、样式、文案、组件 | 构建前端 → 上传 `dist/` 内容 | ❌ 不用，刷新即可 |
| Java 代码、依赖、`application.yml` | 打包 jar → 上传 → 重建 backend | ✅ 重建 backend |
| `.env`（密码、密钥、域名） | 改 `.env` → `up -d backend` | ✅ 重建 backend |
| `nginx/conf.d/*.conf` | `nginx -t` → `restart nginx` | ✅ 重启 nginx |
| 数据库表结构 | JPA 启动时自动 `update`；**先备份** | ✅ 重建 backend |

> 通用于所有情况：**动手前先备份数据库**（第 2 节，30 秒）。

## 3. 只改前端（最常见）

### 3.1 本地构建

```powershell
cd D:\aiconding\fcdzy_site\frontend
npm run build          # 产出 dist\
```

### 3.2 上传

把 `dist\` 里的**内容**（`assets/`、`index.html`、`favicon.svg`）覆盖到 `/opt/fcdzy/www/`。
用 WinSCP / FinalShell / 宝塔文件管理器都行，注意是传 `dist` 里的东西，不是 `dist` 目录本身。

> 更稳的做法：先删掉服务器上的旧 `assets/`，再传新的，避免旧 chunk 堆积。

### 3.3 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://fcdzy.xyz/

```

浏览器 **Ctrl + F5** 强刷（`index.html` 引用的 js/css 带 hash，文件名变了就是新版）。

> 不需要重启任何容器：`www` 是挂载进去的。

## 4. 只改后端

### 4.1 本地打包

```powershell
cd D:\aiconding\fcdzy_site\backend
mvn -DskipTests clean package
```

产物：`target\fcdzy-site-1.0.0.jar`

记下校验值，上传后比对：

```powershell
Get-FileHash target\fcdzy-site-1.0.0.jar -Algorithm MD5
```

> 打包规则已在 `pom.xml` 里排除 `application-db.yml` / `application-local.yml`，
> 所以 jar 里**不会**带数据库密码和密钥，部署时靠环境变量。本地开发需要的这两个文件放在
> `backend/config/`（不进 git，也不进 jar）。

### 4.2 上传并校验

上传到 `/opt/fcdzy/backend/`，**文件名必须保持** `fcdzy-site-1.0.0.jar`。

```bash
cd /opt/fcdzy/backend
md5sum fcdzy-site-1.0.0.jar          # 应和本地一致
ls -l fcdzy-site-1.0.0.jar           # 大小应和本地一致
```

### 4.3 保留上一版（方便回滚）

```bash
cp fcdzy-site-1.0.0.jar fcdzy-site-1.0.0.jar.bak-$(date +%F_%H%M)
```

### 4.4 重建后端容器

```bash
cd /opt/fcdzy
docker compose up -d --build backend
docker compose logs --tail=40 backend
```

正常会看到：

```
Tomcat started on port 8080 (http)
Started SiteApplication in x.xxx seconds
```

### 4.5 验证

```bash
curl -s https://fcdzy.xyz/api/public/articles?pageNum=1\&pageSize=1 | head -c 120
curl -s -o /dev/null -w "%{http_code}\n" https://fcdzy.xyz/
```

第一条要返回 `{"code":0,...}`，第二条返回 `200`。


## 11. 常见坑（都实际踩过）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 容器 `Up` 但接口全 502 | 应用启动失败（DB 连不上），PID 1 不是 JVM 所以容器没退出 | `docker compose logs backend` 看 `APPLICATION FAILED TO START` |
| 容器里连的还是公网数据库地址 | jar 里打进了 `application-db.yml`，覆盖了 `DB_HOST` | 已修：配置文件移出 resources + pom 排除 |
| 上传后启动报 `zip END header not found` / 类缺失 | jar 没传完整 | `md5sum` 比对，重传 |
| 改了 `.env` 没生效 | 没重建容器 | `docker compose up -d backend` |
| 登录报 `Request failed with status code 403` | CORS 白名单缺站点域名 | 已修：从 `SITE_WEB_URL` 推导；确认 `.env` 有该变量 |
| 图片全是灰块 / 破图 | OSS 防盗链白名单缺域名 | OSS 控制台 → 防盗链，加 `https://fcdzy.xyz`、`https://www.fcdzy.xyz` |
| 页面还是旧的 | 浏览器缓存 | Ctrl + F5；确认 `www/index.html` 时间戳 |
| 定时发布执行了两次 | 本机和服务器各跑了一个后端 | 只保留线上一个实例 |
| 本地 `mvn spring-boot:run` 连不上库 | 缺 `backend/config/application-db.yml` | 从 `.example.yml` 复制一份填好 |
| 手滑 `docker compose down -v` | `-v` 会删数据卷 | 永远不要加 `-v` |

## 13. （可选）后端一键更新脚本

放在服务器 `/opt/fcdzy/update-backend.sh`：

```bash
#!/usr/bin/env bash
# 用法：把新 jar 传到 /opt/fcdzy/backend/ 后执行本脚本
set -e
cd /opt/fcdzy
[ -f backend/fcdzy-site-1.0.0.jar ] || { echo "缺少 jar"; exit 1; }

cp -f backend/fcdzy-site-1.0.0.jar "backend/fcdzy-site-1.0.0.jar.bak-$(date +%F_%H%M)"
docker compose up -d --build backend

echo "等待启动..."
for i in $(seq 1 30); do
  if curl -sf "https://fcdzy.xyz/api/public/articles?pageNum=1&pageSize=1" >/dev/null; then
    echo "✅ 更新完成"
    exit 0
  fi
  sleep 3
done

echo "❌ 启动异常，最近日志："
docker compose logs --tail=40 backend
exit 1
```

```bash
chmod +x /opt/fcdzy/update-backend.sh
```

以后后端更新只需：传 jar →（自动备份旧版）→ 一行命令：

```bash
/opt/fcdzy/update-backend.sh
```

## 15. 安全加固清单

### 15.1 Nginx 安全响应头（一次性配置）

在 `/opt/fcdzy/nginx/conf.d/fcdzy.conf` 的 **443 server 块**里加：

```nginx
add_header Strict-Transport-Security "max-age=15552000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
```

生效：

```bash
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
curl -I https://fcdzy.xyz | grep -iE 'strict-transport|x-content-type|x-frame|referrer-policy|permissions-policy'
```

> CSP 暂时不要加：后台编辑器会从 unpkg 加载 prettier / katex / cropper / screenfull，
> 直接上 `script-src 'self'` 会让后台的格式化、公式、图片裁剪、全屏失效。
> 要上 CSP 得单独一轮，先 `Content-Security-Policy-Report-Only` 观察。

### 15.2 登录防爆破（代码已内置）

同一 IP 连续失败 5 次 → 锁 10 分钟，**锁定期间密码正确也拒绝**。

- 阈值可调：`.env` 里加 `LOGIN_MAX_ATTEMPTS=5`、`LOGIN_LOCK_MINUTES=10`
- 被误锁怎么办：**重启后端即可清空**（状态在内存里）
  ```bash
  cd /opt/fcdzy && docker compose restart backend
  ```
- 只按 IP 锁，不按用户名锁——避免别人拿你的用户名把你自己锁死

### 15.3 评论防垃圾（代码已内置）

| 机制 | 行为 |
| --- | --- |
| 蜜罐字段 | 表单里有个视觉隐藏的「个人网站」输入框，机器人会填 → 后端静默丢弃（返回成功但不入库） |
| 提交耗时 | 打开表单到提交 < 2 秒 → 拒绝「提交过快」 |
| IP 限流 | 同一 IP 30 秒 1 条、每小时 10 条（原有） |

### 15.4 其它建议（尚未做）

- JWT 目前存在 localStorage：一旦有 XSS 会被读走，后续可评估改 httpOnly Cookie + CSRF token
- 备份要**异地**一份（同机备份挡不住删库），并定期演练恢复
- 后台编辑器从 unpkg 加载的 prettier/katex/cropper 建议后续本地化（顺便才能上严格 CSP）

## 16. 数据备份与恢复演练

### 16.1 文章「可读备份」：后台一键导出

后台 → 文章管理 → 右上角 **「导出全部文章」** → 下载 `fcdzy-articles-请日期.zip`。

包内结构：

```
articles/001-<slug>.md     每篇文章（YAML front matter + 原始 Markdown）
manifest.csv               索引表（Excel 可直接打开：标题/分类/标签/状态/阅读数）
README.txt                 说明
```

用途：**数据库之外的第二份备份**。库挂了或被清空，解压这个包就能拿回所有正文，
也能直接导入 Typora / Obsidian / Hexo / Hugo。

> 建议：每次写完一批重要文章就导出一次，存到本地硬盘或网盘（跟数据库备份分开存）。

### 16.2 数据库备份（cron，每天 3:00）

确认已配置（第 12 节有命令）：

```bash
crontab -l | grep backup.sh
ls -lh /opt/fcdzy/backups | tail -3
```

### 16.3 恢复演练（**每月一次，很重要**）

备份没验证过就等于没有备份。仓库里的 `deploy/restore-drill.sh` 会把最新的 dump
恢复到一个**临时库**，逐表核对行数，跑完自动删除临时库，不影响线上。

上传脚本并执行：

```bash
# 本地
scp deploy/restore-drill.sh root@8.138.239.19:/opt/fcdzy/
# 服务器
chmod +x /opt/fcdzy/restore-drill.sh
export MYSQL_CONTAINER=<你的mysql容器名>
export MYSQL_ROOT_PASSWORD=<root密码>
/opt/fcdzy/restore-drill.sh
```

输出会逐表打印「线上 N 行 / 恢复 N 行」，全绿即表示这份备份可以用于灾难恢复：

```
① 校验压缩包完整性...  ✅ gzip 完整
③ 导入到临时库 fcdzy_site_restore_check ...  ✅ 导入完成
④ 核对行数（线上 vs 恢复）...
   ✅ article      7 行
   ✅ comment      2 行
   ✅ site_config  18 行
⑤ 抽查正文（前 60 个字符）...
✅ 恢复演练通过：这份备份可以用于灾难恢复
```

也可以指定某个历史备份：`./restore-drill.sh /opt/fcdzy/backups/fcdzy_site_2026-11-10_0300.sql.gz`

### 16.4 真出事了的恢复步骤

```bash
cd /opt/fcdzy
# 1) 先停写：只停后端（nginx 会返回 502，但数据不会再变）
docker compose stop backend

# 2) 恢复（会覆盖现有数据！）
gunzip -c backups/fcdzy_site_<日期>.sql.gz \
  | docker exec -i <mysql容器名> mysql -uroot -p'<root密码>' --default-character-set=utf8mb4 fcdzy_site

# 3) 起来验证
docker compose start backend
curl -s 'https://fcdzy.xyz/api/public/articles?pageNum=1&pageSize=1' | head -c 120
```

> `mysqldump` 里没有 `DROP TABLE`，所以恢复是「覆盖同名表」而不是重建库；
> 如果走的是 ROW 格式 binlog 或需要精确到某个时间点，再考虑 `mysqlbinlog` 回放。

### 16.5 异地副本（别省）

同机备份挡不住「整台机器被删/被清」。至少做一件：

- 把 `/opt/fcdzy/backups` 每天同步到另一台机器（`rsync`/`scp`）
- 或者定时上传到 OSS（`ossutil cp`），保留 30 天
- 或者每周手动把最新备份 + 文章导出包下载到本地电脑
