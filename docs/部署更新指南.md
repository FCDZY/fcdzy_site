# 部署与更新指南（FCDZY 个人博客）

> 服务器：`8.138.239.19`　域名：`https://fcdzy.xyz`　后台入口：`https://fcdzy.xyz/yzdcf/login`
> 本文只讲「日常怎么更新」。第一次部署的完整步骤见 README 和聊天记录。

---

## 0. 现状速查

| 部件 | 位置 / 说明 |
| --- | --- |
| 前端静态文件 | `/opt/fcdzy/www`（以只读方式挂载进 nginx 容器） |
| 后端 jar | `/opt/fcdzy/backend/fcdzy-site-1.0.0.jar` + 同目录 `Dockerfile` |
| Nginx 配置 | `/opt/fcdzy/nginx/conf.d/fcdzy.conf` |
| HTTPS 证书 | Let's Encrypt，`/opt/fcdzy/certbot/conf/live/fcdzy.xyz/` |
| 环境变量（密钥） | `/opt/fcdzy/.env`（权限 600） |
| 编排文件 | `/opt/fcdzy/docker-compose.yml` |
| 数据库 | 你已有的 MySQL 容器（跑在 `fcdzy-net` 网络里，不对外暴露端口） |
| 上传兜底目录 | `/opt/fcdzy/uploads`（图片主要走 OSS） |
| 数据库备份 | `/opt/fcdzy/backups`（cron 每天 3:00） |

容器名：`fcdzy-backend`、`fcdzy-nginx`；MySQL 容器名以 `docker ps` 为准。

**关键约定**：后端所有敏感配置只走 `.env` 环境变量，jar 里不含任何密钥；数据库地址在容器内用 MySQL 容器名解析，不连公网 IP。

## 1. 先看这张表（决定要做什么）

| 你改了什么 | 需要执行 | 要重启吗 |
| --- | --- | --- |
| Vue 页面、样式、文案、组件 | 构建前端 → 上传 `dist/` 内容 | ❌ 不用，刷新即可 |
| Java 代码、依赖、`application.yml` | 打包 jar → 上传 → 重建 backend | ✅ 重建 backend |
| `.env`（密码、密钥、域名） | 改 `.env` → `up -d backend` | ✅ 重建 backend |
| `nginx/conf.d/*.conf` | `nginx -t` → `restart nginx` | ✅ 重启 nginx |
| 数据库表结构 | JPA 启动时自动 `update`；**先备份** | ✅ 重建 backend |

> 通用于所有情况：**动手前先备份数据库**（第 2 节，30 秒）。

## 2. 通用前置：备份数据库

```bash
# 用你真实的 MySQL 容器名
docker exec <mysql容器名> mysqldump -uroot -p'C3358908684' \
  --default-character-set=utf8mb4 --single-transaction --routines --triggers fcdzy_site \
  | gzip > /opt/fcdzy/backups/manual_$(date +%F_%H%M).sql.gz

ls -lh /opt/fcdzy/backups | tail -3
```

回滚数据时：

```bash
gunzip -c /opt/fcdzy/backups/manual_2026-10-24_1200.sql.gz \
  | docker exec -i <mysql容器名> mysql -uroot -p'C3358908684' --default-character-set=utf8mb4 fcdzy_site
```

## 3. 只改前端（最常见）

### 3.1 本地构建

```powershell
cd D:\aiconding\fcdzy_site\frontend
npm run build          # 产出 dist\
```

### 3.2 上传

把 `dist\` 里的**内容**（`assets/`、`index.html`、`favicon.svg`）覆盖到 `/opt/fcdzy/www/`。
用 WinSCP / FinalShell / 宝塔文件管理器都行，注意是传 `dist` 里的东西，不是 `dist` 目录本身。

> 更稳的做法：先删掉服务器上的旧 `assets/`，再传新的，避免旧 chunk 堆积。

### 3.3 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://fcdzy.xyz/
ls -l /opt/fcdzy/www/index.html      # 时间应是刚刚
```

浏览器 **Ctrl + F5** 强刷（`index.html` 引用的 js/css 带 hash，文件名变了就是新版）。

> 不需要重启任何容器：`www` 是挂载进去的。

## 4. 只改后端

### 4.1 本地打包

```powershell
cd D:\aiconding\fcdzy_site\backend
mvn -DskipTests clean package
```

产物：`target\fcdzy-site-1.0.0.jar`

记下校验值，上传后比对：

```powershell
Get-FileHash target\fcdzy-site-1.0.0.jar -Algorithm MD5
```

> 打包规则已在 `pom.xml` 里排除 `application-db.yml` / `application-local.yml`，
> 所以 jar 里**不会**带数据库密码和密钥，部署时靠环境变量。本地开发需要的这两个文件放在
> `backend/config/`（不进 git，也不进 jar）。

### 4.2 上传并校验

上传到 `/opt/fcdzy/backend/`，**文件名必须保持** `fcdzy-site-1.0.0.jar`。

```bash
cd /opt/fcdzy/backend
md5sum fcdzy-site-1.0.0.jar          # 应和本地一致
ls -l fcdzy-site-1.0.0.jar           # 大小应和本地一致
```

### 4.3 保留上一版（方便回滚）

```bash
cp fcdzy-site-1.0.0.jar fcdzy-site-1.0.0.jar.bak-$(date +%F_%H%M)
```

### 4.4 重建后端容器

```bash
cd /opt/fcdzy
docker compose up -d --build backend
docker compose logs --tail=40 backend
```

正常会看到：

```
Tomcat started on port 8080 (http)
Started SiteApplication in x.xxx seconds
```

### 4.5 验证

```bash
curl -s https://fcdzy.xyz/api/public/articles?pageNum=1\&pageSize=1 | head -c 120
curl -s -o /dev/null -w "%{http_code}\n" https://fcdzy.xyz/
```

第一条要返回 `{"code":0,...}`，第二条返回 `200`。

## 5. 前后端一起改

顺序：**先备份 → 后端（jar + 重建）→ 前端（dist）**。

因为前端可能调用了新接口，先上后端可以避免接口 404。

```bash
# 1) 备份
# 2) 上传 jar → docker compose up -d --build backend → 看日志
# 3) 上传 dist → Ctrl+F5
```

## 6. 只改配置（.env）

```bash
cd /opt/fcdzy
vi .env                    # 改密码 / 密钥 / 域名
docker compose up -d backend   # 必须重建，环境变量才会生效
docker compose logs --tail=20 backend
```

> ⚠️ 只改 `.env` 不重建容器，容器里还是旧值。

**注意**：`JWT_SECRET` 一改，所有已登录的 token 立即失效，需要重新登录。

常用变量：

```bash
SITE_WEB_URL=https://fcdzy.xyz
SITE_BASE_URL=https://fcdzy.xyz
DB_HOST=<mysql容器名>
DB_NAME=fcdzy_site
DB_USERNAME=fcdzy_site_user
DB_PASSWORD=...
JWT_SECRET=...
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
MAIL_USERNAME=...
MAIL_SMTP_CODE=...
```

## 7. 改 Nginx 配置 / 证书

```bash
docker compose exec nginx nginx -t          # 语法检查，必须先过
docker compose restart nginx
```

证书续期（Let's Encrypt 90 天，cron 已配每天检查）：

```bash
docker run --rm -v /opt/fcdzy/certbot/conf:/etc/letsencrypt \
  -v /opt/fcdzy/certbot/www:/var/www/certbot \
  certbot/certbot renew --webroot -w /var/www/certbot --dry-run   # 演练
```

手动续一次并重载：

```bash
/opt/fcdzy/renew-cert.sh
```

**换了域名**要同步三处：DNS A 记录、`.env` 里的 `SITE_WEB_URL` / `SITE_BASE_URL`、**OSS 防盗链白名单**。

## 8. 数据库变更

- 新增表 / 加字段：JPA `ddl-auto: update` 启动时自动做，重建后端即可。
- **删字段 / 改类型**：JPA 不会删列，需要手工执行 SQL（先备份）。
- 任何表结构变更前，先按第 2 节备份。

## 9. 回滚

### 后端

```bash
cd /opt/fcdzy/backend
ls -lt *.bak-* | head -3
cp fcdzy-site-1.0.0.jar.bak-2026-10-24_1200 fcdzy-site-1.0.0.jar
cd /opt/fcdzy && docker compose up -d --build backend
docker compose logs --tail=20 backend
```

### 前端

保留一份旧 `www` 备份即可：

```bash
cd /opt/fcdzy
tar czf www-backup-$(date +%F_%H%M).tgz www
# 回滚
tar xzf www-backup-xxx.tgz
```

### 数据库

用第 2 节导出的 `.sql.gz` 覆盖导入（**会丢掉备份之后的写入**，谨慎）。

## 10. 每次更新后的验收清单

| 检查 | 命令 | 期望 |
| --- | --- | --- |
| 首页 | `curl -s -o /dev/null -w "%{http_code}" https://fcdzy.xyz/` | `200` |
| 文章接口 | `curl -s 'https://fcdzy.xyz/api/public/articles?pageNum=1&pageSize=1'` | `{"code":0,...}` |
| 登录接口（带 Origin） | 见下方命令 | `401`（账号错）或 `200`，**不能是 403** |
| 后台页面 | 打开 `https://fcdzy.xyz/yzdcf/login` | 能登录 |
| 图片 | 首页 Banner / 封面 | 能显示（不是灰块） |
| 容器 | `docker compose ps` | backend / nginx 都是 `Up` |
| 数据库连通 | `docker compose logs --tail=30 backend \| grep -i error` | 无报错 |

登录接口检查（重点：403 说明 CORS 白名单没包含站点域名）：

```bash
curl -i -X POST -H "Content-Type: application/json" -H "Origin: https://fcdzy.xyz" \
  -d '{"username":"x","password":"y"}' https://fcdzy.xyz/api/auth/login
```

## 11. 常见坑（都实际踩过）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 容器 `Up` 但接口全 502 | 应用启动失败（DB 连不上），PID 1 不是 JVM 所以容器没退出 | `docker compose logs backend` 看 `APPLICATION FAILED TO START` |
| 容器里连的还是公网数据库地址 | jar 里打进了 `application-db.yml`，覆盖了 `DB_HOST` | 已修：配置文件移出 resources + pom 排除 |
| 上传后启动报 `zip END header not found` / 类缺失 | jar 没传完整 | `md5sum` 比对，重传 |
| 改了 `.env` 没生效 | 没重建容器 | `docker compose up -d backend` |
| 登录报 `Request failed with status code 403` | CORS 白名单缺站点域名 | 已修：从 `SITE_WEB_URL` 推导；确认 `.env` 有该变量 |
| 图片全是灰块 / 破图 | OSS 防盗链白名单缺域名 | OSS 控制台 → 防盗链，加 `https://fcdzy.xyz`、`https://www.fcdzy.xyz` |
| 页面还是旧的 | 浏览器缓存 | Ctrl + F5；确认 `www/index.html` 时间戳 |
| 定时发布执行了两次 | 本机和服务器各跑了一个后端 | 只保留线上一个实例 |
| 本地 `mvn spring-boot:run` 连不上库 | 缺 `backend/config/application-db.yml` | 从 `.example.yml` 复制一份填好 |
| 手滑 `docker compose down -v` | `-v` 会删数据卷 | 永远不要加 `-v` |

## 12. 命令速查

```bash
# 目录
cd /opt/fcdzy

# 状态与日志
docker compose ps
docker compose logs --tail=50 backend

# 后端更新

# Nginx 改配置
docker compose exec nginx nginx -t && docker compose restart nginx

# 备份

  --single-transaction --routines --triggers fcdzy_site | gzip > /opt/fcdzy/backups/x.sql.gz

# 进容器排查
docker compose exec backend sh
docker compose exec nginx sh

# 重启全部（不动 MySQL）
docker compose restart
```

## 13. （可选）后端一键更新脚本

放在服务器 `/opt/fcdzy/update-backend.sh`：

```bash
#!/usr/bin/env bash
# 用法：把新 jar 传到 /opt/fcdzy/backend/ 后执行本脚本
set -e
cd /opt/fcdzy
[ -f backend/fcdzy-site-1.0.0.jar ] || { echo "缺少 jar"; exit 1; }

cp -f backend/fcdzy-site-1.0.0.jar "backend/fcdzy-site-1.0.0.jar.bak-$(date +%F_%H%M)"
docker compose up -d --build backend

echo "等待启动..."
for i in $(seq 1 30); do
  if curl -sf "https://fcdzy.xyz/api/public/articles?pageNum=1&pageSize=1" >/dev/null; then
    echo "✅ 更新完成"
    exit 0
  fi
  sleep 3
done

echo "❌ 启动异常，最近日志："
docker compose logs --tail=40 backend
exit 1
```

```bash
chmod +x /opt/fcdzy/update-backend.sh
```

以后后端更新只需：传 jar →（自动备份旧版）→ 一行命令：

```bash
/opt/fcdzy/update-backend.sh
```

## 14. 本地开发要用的两条命令

```powershell
# 后端（需要 backend\config\application-db.yml 和 application-local.yml 存在）
cd D:\aiconding\fcdzy_site\backend
mvn spring-boot:run

# 前端
cd D:\aiconding\fcdzy_site\frontend
npm run dev
```

本地跑的时候记得把线上后端停掉，或者别让本地也跑定时发布（会重复执行）。
