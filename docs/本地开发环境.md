# 本地开发环境

> 目标：改完代码 **1 分钟看到效果**，而不是打包 → 上传 → 重启 → 刷新线上。

---

## 一、一条命令启动

> ⚠️ **必须用 PowerShell 或 `dev.cmd`，不能直接在 cmd 里敲 `.ps1`**
> 你的 PowerShell 执行策略是 `Restricted`，双击/直接运行 `.ps1` 不会有任何反应（会被关联程序打开）。
> 所以提供了 `.cmd` 包装：跑的时候用 `powershell -ExecutionPolicy Bypass` 转一层。

**方式 A：cmd 里（最简单）**

```bat
cd /d D:\aiconding\fcdzy_site
scripts\dev.cmd
```

**方式 B：PowerShell 里**

```powershell
cd D:\aiconding\fcdzy_site
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

**方式 C：资源管理器里双击**

```
D:\aiconding\fcdzy_site\scripts\dev.cmd
```

它做的事：

1. 检查本地 MySQL（`MySQL80` 服务）是否在 3306
2. 检查 8080 / 5173 有没有被占用
3. 用**本地开发库** `fcdzy_site_local` 启动后端（通过环境变量覆盖，不改任何配置文件）
4. 启动前端 Vite
5. 等两个端口都就绪后，自动打开 http://localhost:5173

输出长这样：

```
  启动本地开发环境
  ------------------
  MySQL :3306 正常
  开发库：fcdzy_site_local（7 篇文章）
  启动后端……（首次编译约 30~60 秒）
  后端 :8080 就绪
  启动前端……
  前端 :5173 就绪

  打开 http://localhost:5173 即可预览（改代码即时生效）
  改完不用了：scripts\dev.cmd -Stop
```

## 二、常用命令

| 命令 | 作用 |
| --- | --- |
| `scripts\dev.cmd` | 启动（cmd / 双击都能用；默认用 `fcdzy_site_local` 库） |
| `scripts\dev.cmd -Stop` | 停止前后端，释放端口 |
| `scripts\dev.cmd -Status` | 看现在是不是在跑、用的哪个库 |
| `scripts\dev.cmd -NoOpen` | 启动但不自动开浏览器 |
| `scripts\dev.cmd -DbName fcdzy_site` | 换一个库启动（比如想看原始快照） |
| `scripts\dev.cmd -DbPassword 你的密码` | 配置文件里的密码不对时手动指定 |

## 三、两个数据库，各管什么

| 库 | 用途 | 谁能改 |
| --- | --- | --- |
| `fcdzy_site` | **参考快照**：你导入的线上数据，用来对照/查资料 | 尽量别动 |
| `fcdzy_site_local` | **本地开发库**：随便删文章、点"彻底删除"、跑测试 | 随便折腾 |

`dev.ps1` 默认连的是 `fcdzy_site_local`，所以你本地怎么造都**碰不到** `fcdzy_site`，更碰不到线上。

### 本地库的三个操作

```powershell
# 看两个库的概况
scripts\db-local.cmd -Action info

# 把 fcdzy_site 重新复制一份到 fcdzy_site_local（重置开发库）
scripts\db-local.cmd -Action clone

# 清掉开发库里的测试残留（回收站、临时文章、smoke 评论、前端错误）
scripts\db-local.cmd -Action clean
```

输出示例：

```
  本地数据库概况
  --------------
  fcdzy_site           文章 7 篇   回收站 0 篇   前端错误 0 条
  fcdzy_site_local     文章 7 篇   回收站 0 篇   前端错误 0 条
```

## 四、为什么不会误连线上

`dev.ps1` 用两个保险：

1. **环境变量覆盖**：设置 `SPRING_DATASOURCE_URL/USERNAME/PASSWORD`，Spring Boot 里环境变量优先级高于配置文件，所以 `backend\config\application-db.yml` 写什么都不影响
2. **本机校验**：读到的数据库地址如果不是 `localhost` / `127.0.0.1`，脚本会**直接报错退出**，必须显式加 `-AllowRemote` 才放行

> 也就是说：以前那套「备份配置 → 改成 localhost → 跑完再还原」的流程彻底不需要了，不会再有"忘了还原"的风险。

数据库账号从 `backend\config\application-db.yml` 读，这个文件：

- 在 `.gitignore` 里，不进仓库
- 在 `pom.xml` 的 `<resources><excludes>` 里，不进 jar
- 服务器用的是自己 `/opt/fcdzy/config/application-db.yml`

## 六、三种"看效果"的方式，什么时候用哪个

| 方式 | 什么时候用 | 耗时 |
| --- | --- | --- |
| `.\scripts\dev.ps1` → 热更新 | 日常改样式、改交互、写新功能（**90% 的场景**） | 启动 1 分钟，之后改一次约 0.3 秒 |
| `npm run build` + `npm run preview` | 上线前验证打包产物（能发现 dev 环境掩盖的问题：按需引入漏样式、资源路径） | 30 秒 |
| 部署到线上 | 最后一步 | 打包 + 上传 + 重启 |

## 七、常见问题

**Q：双击 / 在 cmd 里敲 `.\scripts\dev.ps1` 没反应？**
因为你的 PowerShell 执行策略是 `Restricted`，`.ps1` 不能直接执行。
改用 `scripts\dev.cmd`（内部用 `-ExecutionPolicy Bypass` 转一层），或者：
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```
想彻底解决（可选，一次性）：在 PowerShell 里执行
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Q：`MySQL :3306` 报错？**
启动 MySQL80 服务：`net start MySQL80`（或用服务管理器）。

**Q：`端口已被占用：:8080`？**
先 `.\scripts\dev.ps1 -Stop`。如果还占用，可能是别的程序（比如之前手动开的 `mvn spring-boot:run`），用任务管理器结束。

**Q：后端起来了但前端 502 / 接口报错？**
看 `frontend\dev-frontend.log`；Vite 代理指向 `127.0.0.1:8080`，后端没起来就会报错。

**Q：想用最新的线上数据调试？**
1. 在服务器上导出一份（`deploy/restore-drill.sh` 用的是同样的方式）
2. 本地：`mysql -uroot -p -e "DROP DATABASE fcdzy_site"` 重建后导入
3. `scripts\db-local.cmd -Action clone` 复制到开发库

**Q：本地测试产生了脏数据？**
`scripts\db-local.cmd -Action clean`，或者直接 `-Action clone` 重置。

**Q：脚本里的中文显示成乱码？**
`scripts\*.ps1` 都是 **UTF-8 with BOM**（PowerShell 5.1 需要 BOM 才认中文）。如果你用编辑器另存，请保持 BOM。
